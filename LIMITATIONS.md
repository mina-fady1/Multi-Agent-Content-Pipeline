# Limitations

- Demo mode is a deterministic simulation. It exercises the complete pipeline but makes no LLM call, so its zero token/cost report is not evidence of live model quality.
- Live Gemini runs require a valid `GEMINI_API_KEY`, access to the configured `GEMINI_MODEL`, and available quota. A successful single request does not guarantee that a full six-slot run will fit the project's quota.
- Live image generation uses separate Gemini image-model requests and can exhaust image-model quota independently of text requests. The current API path requests JPEG output. If a model times out or is unavailable, the Visual Agent tries the next model in `GEMINI_IMAGE_MODELS`; with `GEMINI_IMAGE_FALLBACK=pillow`, it renders the image locally. Without that fallback, the accepted piece is still exported with a grounded visual spec and a blank image field for later rendering.
- The KB is curated and offline. This repository does not fetch arbitrary URLs during demo runs. A supplied focus that cannot resolve to a KB entry is isolated and dropped with a source failure; there is no claim that the KB is exhaustive or current.
- References identify primary documentation, but the engine verifies source IDs and bounded evidence mappings rather than proving formal semantic entailment. Reviewer model scores can miss a subtle contradiction, and Python string checks cannot understand every linguistic paraphrase.
- Token accounting depends on Gemini usage metadata. Gemini may report additional token categories (cached, thinking, tool-use prompt, tool-use response), and missing usage or missing pricing stays unknown in live mode; no current API rate is hardcoded. Prices must be reviewed for the exact model in `config/model_pricing.json`. Cost computation returns unknown when a billable category (e.g. cached tokens, thinking tokens, tool tokens) is present but has no configured rate, to avoid fabricating a price.
- Provider retries are bounded and slot failures are isolated, but persistent quota, authentication, model-availability, or malformed-response errors can still drop a slot. The pipeline does not silently substitute demo output or another Gemini model.
- Tweet length uses a conservative Python character count, not X's weighted Unicode counter. A scheduler may apply different display limits.
- Pillow cards are educational renderings with local fonts and no accessibility guarantee beyond generated alt text. They are PNG files, not hosted media URLs; upload is a separate scheduler step. Font rendering degrades gracefully to the Pillow default font when DejaVuSans is unavailable.
- The allowlist is exact and empty by default. Adding an allowed URL requires a human review of both the URL and the related approved company fact. URL normalization strips scheme/host casing and rejects user:password URLs, but path/query/fragment are compared exactly.
- The pipeline provides content QA and traceability. It is not a smart-contract audit, legal opinion, incident response service, or guarantee of protocol safety.
- The Ollama harness (`run_ollama_piece.py`, `run_ollama_week.py`) is a local test path, not a production provider. Small local models produce lower-quality output, may score rubric criteria incorrectly despite normalization, and the adapter's heuristics (percentage-to-scale normalization, criterion ID aliasing) do not cover all possible model output variations. Ollama runs always force Pillow image rendering and do not attempt Gemini image generation.
- The reviewer's per-criterion minimum gate catches individual weak scores even when the weighted average passes, but model-supplied scores are still subjective. A model that inflates every score can bypass the reviewer gate; deterministic grounding and hard-rule gates remain the non-overridable safety net.
- The Gemini provider disables the SDK's own retry policy to keep the bounded retry budget predictable. Older SDK releases that do not support `HttpRetryOptions` fall back to dict-shaped options or a key-only client.
- Evidence grounding verification uses token overlap heuristics: at least one meaningful term from a claim must appear in the cited evidence. This catches forged citations but cannot detect semantic contradictions, negations, or subtle misrepresentations.
- Hyphens and underscores are normalized as word separators for grounding; the check still cannot prove full semantic entailment.
- The shipped weekly plan is deliberately fixed at six slots. Larger plans need a corresponding validator and quota/concurrency policy change.
- Visual specifications remain available when Gemini visual or image generation is unavailable. A real generated image requires an enabled image model with available quota; `GEMINI_IMAGE_FALLBACK=pillow` is the local fallback.
- The `EvidenceLookup` class facade and the `verify_claim_support` function are shared by both Research and Reviewer agents. A change to evidence retrieval or grounding logic affects both agents simultaneously.
